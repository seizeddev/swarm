# Working principle

- Do everything correctly. No shortcuts.
- Work end-to-end (E2E): finish the whole task, not just a part of it.
- Never guess. Act on knowledge — verify with code analysis, the docs, online research, or by running it.
- If you don't know, find out. Don't assume.

# Project knowledge (learnings)

## Build & verify

- **Rust isn't on `PATH`** in this env: prefix with `export PATH="$HOME/.cargo/bin:$PATH"`.
- Frontend: `pnpm test` / `pnpm test:coverage` (≥85% gate) / `pnpm build` (= `tsc` typecheck + vite). Rust: from `src-tauri/`, `cargo test` + `cargo clippy --all-targets -- -D warnings` + `cargo fmt --check`.
- **Zero `unwrap/expect/panic!` in production Rust** (only the Tauri entrypoint in `lib.rs`). Keep it that way; errors go through `error.rs`.
- **Every source file carries an SPDX header** `// SPDX-License-Identifier: GPL-3.0-or-later` (CSS uses `/* */`). Add it to any new file. Don't strip trailing newlines (breaks `cargo fmt --check`/prettier).

## License

- **GPL-3.0-or-later** (copyleft — chosen to prevent closed-source commercial forks). `LICENSE`, `Cargo.toml`, `package.json` all declare it. Dependencies are compatible (libgit2 is GPLv2-with-linking-exception; Alacritty/Tauri are MIT/Apache).

## Config gotchas

- `tauri.conf.json` security has a strict prod **`csp`** and a permissive **`devCsp`** (for Vite HMR). `style-src` must keep **`'unsafe-inline'`** — React renders inline `style={{…}}` attributes across the UI (~9 components). (The terminal itself no longer needs it — it's a `<canvas>` now, not the old inline-styled cell grid — but the rest of the app still does.) Verified rendering in both dev and a release binary.
- Keep `version` identical across `package.json`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`, and `src-tauri/Cargo.lock` (the lockfile's `swarm` entry — `cargo update -p swarm --precise <v>`).

## Terminal

- **Renderer: GPU `<canvas>`, not DOM.** The frontend paints the Rust-streamed grid onto one `<canvas>` via a `RendererBackend` (`src/lib/term/`): **WebGL2** primary (instanced quads), **Canvas2D** fallback/baseline, chosen by `createRenderer` (WebGL2 try → Canvas2D catch; context-loss auto-rebuilds). Both share **one glyph atlas** (`atlas.ts`) rasterized on a 2D offscreen canvas, so WebGL text is pixel-identical to Canvas2D (no blurry-WebGL). The model/decode/metrics/input/select/mode logic is pure & unit-tested in `src/lib/term/*`; the four DOM/GPU files (`atlas`/`renderer`/`canvas2d`/`webgl2`) are coverage-excluded and verified live. **Gotcha:** `GlyphAtlas.get()` must bump `version` on every cache-miss rasterize, or WebGL2 uploads the glyph texture only on frame 1 and streamed text never reaches the GPU (you see bg+cursor but no text). Cell metrics are locked to **integer device px** (kills the old fractional-width drift); `.term` CSS sets `letter-spacing:0` + ligatures off so the measured advance matches the rasterized glyph.
- **Wire protocol is v2** (`encode` in `terminal.rs` ↔ `decodeUpdate` in `lib/term/grid.ts`): 30-byte header with a leading version byte plus `mode`/`displayOffset`/`history`; per-run OSC 8 hyperlink gated by flag bit 7. Bump `WIRE_VERSION` on both sides together — the decoder drops a mismatched frame. The core also exposes `pty_scroll` (scrollback) and `pty_selection_text` (copy through scrollback via `bounds_to_string`), and forwards OSC 52 *copy* as `term:clipboard` (OSC 52 *paste*/`ClipboardLoad` stays disabled = `Osc52::OnlyCopy`, deliberate anti-exfiltration, like the inert bell).
- **Agents are spawned through the user's interactive login shell on Unix** — `terminal.rs` `build_command` is `#[cfg(unix)]` `$SHELL -ilc 'exec "$0" "$@"' <command> <args…>`, **not the command directly. Do not "simplify" this back to a direct spawn.** A real terminal emulator does the same; it makes agents inherit the user's full env (PATH, locale, and personal settings). The concrete bug it fixes: Claude Code only uses the full-height alternate screen when it sees `CLAUDE_CODE_NO_FLICKER` (a user's `~/.zshrc` setting). A GUI/`.dmg` launch only carries a minimal launchd env, so a direct spawn rendered Claude inline ("terminal cut off at the bottom") — **only in packaged builds, not in `tauri dev`/shell launches**. Never *force* such a var from swarm; load their shell instead. The `#[cfg(windows)]` arm spawns the command directly (a GUI process already inherits the full env, and there's no portable login-shell convention); the shell pane resolves to `powershell` via `agents.rs::default_shell`.
- **Never send a degenerate PTY size.** `Terminal.tsx` `measure()`/`measureFraction()` return `null` for a not-yet-laid-out (0×0) pane; the spawn waits for a real size (`measureReady`). A 2×1/80×24 resize slipping through wedges a TUI's layout. The canvas grid is always correctly sized — terminal-fill problems are almost always the *agent's* render mode (alt-screen vs inline), not swarm's geometry. Fits now use **stable-commit** (commit a size only after it repeats identically across two frames), which replaced the old rAF+60ms+250ms+`fonts.ready`+RO settle-storm that could land a different `floor()` row count — the "random few-px gap at the bottom" jump.
- **Resize on a layout change is driven from the layout fraction, not `ResizeObserver`.** WKWebView's RO doesn't reliably fire for a height-only grow of a percentage-sized absolutely-positioned pane (closing a split-*down* sibling), so `Terminal.tsx` re-fits in a `useLayoutEffect` from `wPct`/`hPct` × the stable tiling-area pixels (never the lagging element). The fraction is mirrored to refs so deferred fits don't read a stale value, and redundant resends are skipped (an identical winsize is a kernel no-op that *suppresses* the SIGWINCH the next real change needs).
- **`terminal.rs::resize` nudges after a grow.** macOS only raises SIGWINCH on a real winsize change, and Ink/Claude intermittently reads a stale size on it (redraws the old, shorter layout until a keystroke). After a grow, `resize` re-asserts the height off-thread with a brief 1-row toggle (PTY-only, emulator untouched) so the TUI gets a second SIGWINCH and repaints full-height. Don't remove it — it's why closing a split-down pane snaps back instantly instead of "only after I type".

## Agent session restore (cmux-style)

- **Agents (and their launch flags) are restored across restart** via `src-tauri/agent_session.rs` + `agent_hooks.rs`, modeled on cmux. Every PTY is stamped with `SWARM_PANE_ID`; a session-start hook installed in each agent's own config runs `swarm --notify-helper session-start <agent>`, which records `{sessionId, args, cwd}` to `~/.swarm/agent-sessions/<paneId>.json`. On hydrate, `store.ts` rebuilds the native resume command (`claude --resume <id> <flags>`, `codex resume <id>`, …) so a `claude --dangerously-skip-permissions` typed into a shell comes back with the flag. Flags are filtered by a per-agent denylist **ported byte-for-byte from cmux** (`AgentLaunchSanitizerPrimaryPolicies`); swarm's own injected flags (`--session-id`/`--settings`) are dropped.
- **Per-agent capture differs** (all from cmux's real source — don't guess): claude/gemini → `SessionStart` in `settings.json`; cursor → `beforeSubmitPrompt` in `hooks.json` (no SessionStart; id key is `conversation_id`); opencode/amp → a JS/TS **plugin** (id from `event.properties.info.id` / `event.thread.id`); codex → `hooks.json` + `config.toml` `[features] hooks=true` + a `[hooks.state."<realpath>:session_start:0:0"] trusted_hash` (SHA-256 of the sorted-key hook identity — see `codex_command_hook_hash`, golden-hash unit-tested). Codex is wired in the **isolated `CODEX_HOME`** (`prepare_codex_home`), so swarm-launched codex; shell-typed codex uses `~/.codex` which swarm doesn't touch by design. aider has no cmux resume spec → intentionally not restorable.
- Launch flags reach the capture exactly: swarm-launched agents pass `SWARM_AGENT_ARGV_JSON` (spaces survive); shell-typed agents are read off the live process via `ps` (space-free flags only). Claude with no transcript yet (opened, never used → can't `--resume`) **reopens fresh with the flags** rather than dropping to a shell.

## Running / screenshotting the app (macOS)

- The app persists its session to **`~/.swarm/session.json`** (schema in `src/lib/persist.ts`) and restores it on launch. To launch into a specific state (e.g. for a screenshot), **back up the file, seed it** (workspace `repoPath`, a `terminals`/`scm`/`prs` panel, a split `layout`, `claude`/`shell` panes), launch, then **restore the backup**.
- Screen capture needs macOS **Screen Recording + Accessibility** TCC permissions (user-granted; can't be scripted). Get window bounds via `osascript`/System Events, capture with `screencapture -R x,y,w,h`.
- The terminal is a `<canvas>` (WebGL2/Canvas2D); the rest of the UI is DOM. Either way, terminal/git/PR data arrives over Tauri IPC — a plain headless browser pointed at the Vite dev URL renders the shell with **no real data** (and the canvas needs a real WebGL/2D context, which headless setups often lack).
- Running the bare `--no-bundle` binary shows a generic **"exec" Dock icon** (no `Info.plist`); the packaged `.app` shows the real icon.

## Releasing (read before touching `release.yml`)

- Triggered by a `v*` tag; builds all platforms and creates a **draft** release that must be **manually published** (`gh release edit <tag> --draft=false`). Needs the `TAURI_SIGNING_PRIVATE_KEY` repo secret for updater artifacts. The matrix `build` job sits behind the protected `release` Environment, so **approve the pending deployment** first: `gh api -X POST repos/<owner>/<repo>/actions/runs/<run_id>/pending_deployments --input -` with `{"environment_ids":[<id>],"state":"approved"}` (the `-f 'environment_ids[]=…'` form silently no-ops).
- **`v*` tags are PROTECTED — you cannot delete or re-point them** (a repo ruleset rejects `git push origin :refs/tags/vX` and `gh release delete --cleanup-tag` with "Cannot delete this tag", even with admin bypass). So if a tagged build is wrong, **bump to a new version — never re-tag.** (This is why the first published release is `v0.2.1`: `v0.2.0` was tagged but its build had the terminal bug and the tag couldn't be re-pointed.)
- Version bump touches **four** files — `package.json`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`, **and `src-tauri/Cargo.lock`** (`cargo update -p swarm --precise <v>`).
- **`bundle_dmg.sh` is flaky** (its AppleScript layout step + leftover mounted `rw.*.dmg` images block reruns). In CI just rerun; locally, detach stale `/Volumes/swarm*` and delete `rw.*.dmg`, or build the DMG by hand: stage `swarm.app` + an `Applications` symlink and `hdiutil create -volname swarm -srcfolder <stage> -format UDZO <out>.dmg`.
- **`release.yml` uses a two-phase pattern on purpose**: a `create-release` job makes one draft and outputs its `release_id`; every build job uploads via `releaseId`. **Do not** go back to per-job `releaseDraft: true` — parallel matrix jobs then race and produce duplicate drafts with artifacts split across them.
- `tauri-action` intermittently fails uploads with transient **`Bad credentials`** (and `actions/checkout` auth blips). Just `gh run rerun <run-id> --failed` — partial reruns keep `create-release`'s output, so artifacts land in the same draft and `latest.json` merges across platforms.
- Builds are **unsigned** (no Developer ID cert; only "Apple Development" certs exist in the keychain). For local install, ad-hoc sign works: `codesign --force --deep --sign - /Applications/swarm.app`.

## Security & supply chain

- **Threat model + guarantees** live in `SECURITY.md` and `docs/THREAT_MODEL.md`; the updater **key-rotation runbook** is in `SECURITY.md`. Update them when the security posture changes.
- **All GitHub Actions are pinned to commit SHAs** (with a `# vX` comment); Dependabot (`github-actions`) bumps them. When adding a workflow, resolve the SHA with `gh api repos/<owner>/<repo>/commits/<tag>` — never use a moving tag. `dtolnay/rust-toolchain` is a *branch*, so pin the action SHA **and** an explicit `toolchain:` (`1.95.0`; matches local).
- **Release signing is gated behind a protected `release` GitHub Environment** (required reviewers) so the password-protected `TAURI_SIGNING_PRIVATE_KEY` (+ `_PASSWORD`) is exposed only to an approved run — not every matrix build. This sits *on top of* the two-phase create/upload pattern, don't remove either.
- **`cargo-deny` config is `src-tauri/deny.toml`.** Gotchas that took tuning: the `fix-path-env` git dep needs `version = "0.0.0"` in `Cargo.toml` (its rev's version) to clear the wildcard ban; `unmaintained = "workspace"` so un-fixable transitive advisories (gtk-rs GTK3, unic-* via tauri-utils) don't fail the gate while real vulnerabilities still do; `allow-git` lists the one vetted git source. Run `cargo deny check all` before touching deps.
- **Agent session-capture writes into the user's *real* agent configs** (`~/.claude/settings.json`, `~/.gemini/settings.json`, `~/.cursor/hooks.json`, opencode/amp plugin files). These installers are idempotent + defensive (never clobber an unparseable file or unrelated hooks) and the helper is a no-op outside swarm (`SWARM_PANE_ID` unset). This is deliberate (cmux does the same) — it's the only way a *shell-typed* agent gets captured. Codex is the exception: it's wired only into swarm's isolated `CODEX_HOME`, never `~/.codex`.
- **`sha2` + `toml` are direct deps** (already transitive; cargo-deny clean) used only for Codex's hook-trust: SHA-256 of the hook identity must match Codex's own scheme byte-for-byte (sorted keys, no slash escaping — `codex_command_hook_hash`, golden-hash test) or Codex silently rejects the hook; `toml` edits `config.toml`'s `[features]`/`[hooks.state]` tables safely (falls back to verbatim string-append if the user's config doesn't parse, so settings are never lost).
- **Path-allowlist guard** (`src-tauri/src/guard.rs`, `WorkspaceRegistry`): every path-taking command validates against roots the frontend registered via `register_root`. The frontend must call `api.registerRoot(...)` (in `store.ts` `addWorkspace`/`hydrate`) **before** any git/PTY command, registering both the picked path and the canonical `repo.path`. The CSP remains the *primary* defence; this is blast-radius reduction.
- **Fuzzing** is an out-of-tree crate at `src-tauri/fuzz/` (cargo-fuzz, nightly-only, weekly `fuzz.yml`). It is **not** a member of the src-tauri package, so `cargo build`/`clippy`/`cargo-deny` never descend into it. The parser is reached via the `#[doc(hidden)] pub fn __fuzz_parse_notifications` crate-root export.
